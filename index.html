    03 / METHOD

    省下的，
    是汇率里的细节。

    这里没有玄学。把一笔消费拆成“卡组织折算”和“银行购汇”两步，再把费用和返现放进去，结果就清楚了。

    01

    银行牌价，看卖出价

    你用人民币买外币还款，对应的是银行“现汇卖出价”，不是中间价，也不是现钞买入价。买入价和卖出价之间的差额，就是银行点差。

    02

    卡组织汇率，默认不加点

    Visa、万事达、银联的入账汇率没有稳定的公开静态接口。没有可靠数据就不猜：默认全部 0bp，即按中间价计算；有真实账单后再逐项调整。

    03

    费用和返现，一起算

    货币转换费按折算后金额加收；返现和积分折现按比例抵扣。你可以在“汇率与费用假设”里把每条路径改成自己的真实费率。

    预计入账 = 外币金额 × 卡组织折算率 × 银行购汇率 × (1 + 货转费) − 返现 / 积分折现

    本页是消费前的决策辅助，不是结算报价。银行牌价取自中国银行、中国工商银行、招商银行、交通银行官网快照；中间价来自 ExchangeRate-API；卡组织汇率与卡片费率为可调假设。实际入账金额、汇率时点、返现资格均以发卡行和卡组织为准。若收单方提供动态货币转换（DCC），通常应拒绝人民币定价，选择当地币种结算。

    04 / DATA

    数据从哪来，
    多久刷新？

    哪些是官网牌价，哪些只是可调假设，必须分开说清楚。否则“最优”只是一个看起来很精确的猜测。

    官网牌价 01

    中行 · 工行 · 招行 · 交行

    各银行官网的现汇买入价 / 现汇卖出价，按抓取时的牌价生成快照。页面不直接请求银行接口，避免跨域和密钥问题。

    更新方式 运行脚本 / GitHub Action
    公开接口 02

    ExchangeRate-API 中间价

    仅作为卡组织汇率的基准。它不是银行成交价，也不代表卡组织最终入账价，只用来说明“中间价在哪里”。

    更新方式 随牌价快照一起抓取
    无公开数据 03

    卡组织汇率加点

    没有可靠的公开点数数据，所以默认全部为 0bp，直接按中间价计算。它不是官方卡组织报价，需要按你的真实账单再调整。

    默认值 0bp · 可调
    用户输入 04

    路径费率与返现

    没有可靠的实时卡权益数据，所以货转费和返现默认全部为 0。它们不是银行实时权益，也不是你的实际账单；请按自己的卡填写。

    默认值 0% · 可调
    刷新策略

    本地和纯静态页面不会自动刷新牌价。部署到 GitHub 后，仓库内置的 Action 每 6 小时抓取一次并提交新快照，GitHub Pages 随后重新发布；已打开的页面刷新后才会看到新快照。本地可随时手动更新。

    npm run update-rates
